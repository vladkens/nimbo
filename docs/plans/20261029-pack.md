# Packaging

Goal: `nimbo-pack`, a command an app built on nimbo runs locally and in CI to make its release files from its own description, in place of wavo-app's `scripts/dist.py`, `scripts/bundle.py` and its installer work: the files the updater (`src/update.rs`, PR #48) installs from. Asked by the person 2026-10-29: packaging belongs to nimbo.

## Decisions

- Python scripts run with a plain `python3`, not a Rust tool: CI must never compile a packaging tool, and signing runs in a job that compiles nothing (the person's rules, 2026-10-29). An app's CI checks nimbo out at the rev its Cargo.lock pins (`source = "git+https://github.com/vladkens/nimbo…#<sha>"`) and runs `python3 <nimbo>/scripts/pack.py …` from that checkout, macOS's sign job its `dmg`; locally the same through `cargo metadata`'s path to nimbo. Python 3.9+ (macOS's /usr/bin/python3), standard library only; the config from `cargo metadata --no-deps` (JSON), no `tomllib`.
- cargo-packager was checked by wavo-app (v0.11.8 source) and doesn't fit: the identity only from config, `--timestamp` always, fixed names, unpinned linuxdeploy, no aarch64 AppImage from x86_64, the .desktop named after the binary, compiled in CI.
- The app describes itself once in its `Cargo.toml`:

  ```toml
  [package.metadata.nimbo]
  id = "me.vladkens.wavo"        # bundle id, app id, WM_CLASS
  name = "Wavo"                  # shown name, file names
  icon = "assets/icon.png"       # 1024 px PNG
  comment = "Local dictation…"   # one line
  [package.metadata.nimbo.macos]
  accessory = true               # LSUIElement
  usage = { NSMicrophoneUsageDescription = "…" }
  plist = { LSEnvironment = { MallocSpaceEfficient = "1" }, NSSupportsSuddenTermination = false }
  entitlements = "assets/wavo.entitlements"
  [package.metadata.nimbo.linux]
  categories = ["Utility", "Accessibility"]
  deb-depends = ["libasound2"]
  ```

  The version and the binary name are the package's.
- `python3 scripts/pack.py <command> [--target <triple>] [--out target/distrib] [--manifest <app>/Cargo.toml]`, the binary already built (`--bin <path>`, default `target/<triple>/dist/<bin>`):
  - `app` (macOS): `<Name>.app`: Info.plist from the config, the icns (sips, iconutil), signed ad hoc or with `$NIMBO_SIGN_IDENTITY`; the release signing, the DMG, notarization and stapling stay in vladkens/actions' `macos-sign` (a job that compiles nothing), which `dmg` serves: `pack.py dmg <Name>.app` makes `<Name>-v<v>-macos.dmg` (hdiutil UDZO, the `.app` and an /Applications link).
  - `setup` (Windows): `<Name>-v<v>-windows-<x64|arm64>-setup.exe`, Inno Setup from a generated `.iss` (per user, `PrivilegesRequired=lowest`, `{localappdata}\Programs\<Name>`, the uninstaller and the Start menu entry; no AppMutex, no CloseApplications, no `[Run]` after a silent install, which the updater runs as `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /CURRENTUSER`), compiled by ISCC (Inno Setup 6, prebuilt, on the runner or `choco install innosetup`). The exe's icon stays in the app's build script for now.
  - `appimage` and `deb` (Linux): `<Name>-v<v>-linux-<arch>.AppImage` (appimagetool and its runtime pinned by SHA-256, as wavo-app's dist.py) and `<bin>_<v>_<amd64|arm64>.deb` (dpkg-deb: /usr/bin, the .desktop entry with StartupWMClass, the icon in hicolor, `Depends` from the config).
  - `feed [--key <file>] --url <base> <files…>`, the key else from `$UPDATE_KEY`: the signed `update.txt` (scripts/update-feed.py of feat/updater folded in).
  - `feed-key [--repo <owner/name>]`: the one Ed25519 key, in memory only: set as the secret UPDATE_KEY (`gh secret set`), the private key (its seed in hex) on the clipboard for Bitwarden, the public key printed in hex for the app's config.
- Files: `scripts/pack.py` (the command line, the config, `feed`), `scripts/pack_macos.py`, `scripts/pack_windows.py`, `scripts/pack_linux.py`, each importable and testable with `python3 -m doctest` or plain asserts like scripts/size.py; one owner each.

## Tasks

- [ ] 1. The crate, the config and the build step; `feed`.
- [ ] 2. macOS: `.app`, signing, DMG, notarization.
- [ ] 3. Windows: the build-script resources and the Inno installer.
- [ ] 4. Linux: AppImage and `.deb`.
- [ ] 5. wavo-app switched to it (its agent), CI per OS.
- [ ] 6. VM runs: each file installs and starts on its OS; the updater installs from them (with #48).

## Interfaces between the files

- `pack.py`: `@dataclass class Config: id, name, icon: Path, comment, version, bin (the binary's name), macos: dict, linux: dict, root: Path` and `load(manifest: Path) -> Config` (`cargo metadata --no-deps`: the package and its `metadata.nimbo`); `run(*args, **kw)` (subprocess, check=True); `arch(target) -> "x86_64" | "aarch64"`; the subcommands call the OS modules.
- `pack_macos.py`: `app(cfg, binary, out_dir) -> Path` (the `.app`), `dmg(cfg, app, out_dir) -> Path`.
- `pack_windows.py`: `setup(cfg, binary, arch, out_dir) -> Path`.
- `pack_linux.py`: `appimage(cfg, binary, arch, out_dir) -> Path`, `deb(cfg, binary, arch, out_dir) -> Path`.
- Names: `<Name>-v<version>-<platform>.<ext>` with platform `macos`, `windows-x64|arm64` (+ `-setup.exe`), `linux-x86_64|aarch64`; the .deb as Debian names it, `<bin>_<version>_<amd64|arm64>.deb`.
