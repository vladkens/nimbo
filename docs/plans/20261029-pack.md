# Packaging

Goal: `nimbo-pack`, a command an app built on nimbo runs locally and in CI to make its release files from its own description, in place of wavo-app's `scripts/dist.py`, `scripts/bundle.py` and its installer work: the files the updater (`src/update.rs`, PR #48) installs from. Asked by the person 2026-10-29: packaging belongs to nimbo.

## Decisions

- Python scripts run with a plain `python3`, not a Rust tool: CI must never compile a packaging tool, and signing runs in a job that compiles nothing (the person's rules, 2026-10-29). An app's CI checks nimbo out at the rev its Cargo.lock pins (`source = "git+https://github.com/vladkens/nimbo…#<sha>"`) and runs `python3 <nimbo>/scripts/pack.py …` from that checkout, macOS's sign job its `app` and `dmg`; locally the same through `cargo metadata`'s path to nimbo. Python 3.9+ (macOS's /usr/bin/python3), standard library only; the config from `cargo metadata --no-deps` (JSON), no `tomllib`.
- cargo-packager was checked by wavo-app (v0.11.8 source) and doesn't fit: the identity only from config, `--timestamp` always, fixed names, unpinned linuxdeploy, no aarch64 AppImage from x86_64, the .desktop named after the binary, compiled in CI.
- The app describes itself once in its `Cargo.toml`:

  ```toml
  [package.metadata.nimbo]
  id = "me.vladkens.wavo"        # bundle id, app id, WM_CLASS
  name = "Wavo"                  # shown name, file names
  icon = "assets/icon.png"       # 1024 px PNG
  comment = "Local dictation…"   # one line
  [package.metadata.nimbo.macos]
  accessory = true               # LSUIElement
  usage = { NSMicrophoneUsageDescription = "…" }
  plist = { LSEnvironment = { MallocSpaceEfficient = "1" }, NSSupportsSuddenTermination = false }
  entitlements = "assets/wavo.entitlements"
  [package.metadata.nimbo.linux]
  categories = ["Utility", "Accessibility"]
  deb-depends = ["libasound2"]
  ```

  The version and the binary name are the package's.
- `python3 scripts/pack.py <command> [--target <triple>] [--out target/distrib] [--manifest <app>/Cargo.toml]`, the binary already built (`--bin <path>`, default `target/<triple>/dist/<bin>`):
  - `app` (macOS): `<Name>.app`: Info.plist from the config, the icns (sips, iconutil), signed with `$NIMBO_SIGN_IDENTITY`, else a Developer ID in the keychain (with a secure timestamp), else ad hoc in CI, else the app's local identity. `pack.py dmg <Name>.app` makes `<Name>-v<v>-macos-<arch>.dmg` (the arch the binary's by `lipo -archs`, or `--target`; hdiutil UDZO, the `.app` and an /Applications link), signed by the same identity unless ad hoc or none; vladkens/actions' `macos-sign` (a job that compiles nothing) only notarizes and staples it.
  - `setup` (Windows): `<Name>-v<v>-windows-<x64|arm64>-setup.exe`, Inno Setup from a generated `.iss` (per user, `PrivilegesRequired=lowest`, `{localappdata}\Programs\<Name>`, the uninstaller and the Start menu entry; no AppMutex, no CloseApplications, no `[Run]` after a silent install, which the updater runs as `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /CURRENTUSER`), compiled by ISCC: Inno Setup 6.3+ for `x64compatible`; GitHub's windows-latest image has 6.7.1 preinstalled ([Windows2025-VS2026 readme](https://github.com/actions/runner-images/blob/main/images/windows/Windows2025-VS2026-Readme.md), image 20261021.278.1, checked 2026-10-29), so use that and `choco install innosetup` only where it's missing. No `SetupIconFile`: the setup shows Inno's icon, Settings › Apps the exe's own, which stays in the app's build script.
  - `appimage` and `deb` (Linux): `<Name>-v<v>-linux-<arch>.AppImage` (appimagetool and its runtime pinned by SHA-256, as wavo-app's dist.py) and `<bin>_<v>_<amd64|arm64>.deb` (dpkg-deb: /usr/bin, the .desktop entry with StartupWMClass, the 1024 px PNG in hicolor's 1024x1024 and pixmaps, `Maintainer` the first of `authors`, `Depends` from the config); the AppImage takes the PNG as it is.
  - `feed [--key <file>] --url <base> <files…>`, the key else from `$UPDATE_KEY`, given to openssl on stdin: the signed `update.txt` (scripts/update-feed.py of feat/updater folded in). `feed` and `feed-key` need OpenSSL 3 (macOS's /usr/bin/openssl is LibreSSL): the PATH's, else Homebrew's `openssl@3`, else they exit naming `brew install openssl@3`.
  - `feed-key [--repo <owner/name>]`: the one Ed25519 key, in memory only: set as the secret UPDATE_KEY (`gh secret set`), the private key (its seed in hex) on the clipboard (`pbcopy`: it runs on the person's Mac) for Bitwarden, the public key printed in hex for the app's config.
- Files: one `scripts/pack.py`, its sections `# MARK: macOS`, `# MARK: Windows`, `# MARK: Linux` and `# MARK: Feed`, tested with `python3 -m doctest scripts/pack.py` (`make check`). No PNG codec: macOS scales with sips, the others take the 1024 px PNG as it is.

## Interfaces in pack.py

- The core: `@dataclass class Config: id, name, icon: Path, comment, version, bin (the binary's name), macos, linux, windows: dict, publisher, authors, root, target: Path` and `load(manifest: Path) -> Config` (`cargo metadata --no-deps`: the package and its `metadata.nimbo`); `run(*args, **kw)` (subprocess, check=True); `arch(target) -> "x86_64" | "aarch64"`.
- macOS: `app(cfg, binary, out_dir) -> Path` (the `.app`), `dmg(cfg, bundle, target, out_dir) -> Path`.
- Windows: `setup(cfg, binary, arch, out_dir) -> Path`.
- Linux: `appimage(cfg, binary, arch, out_dir) -> Path`, `deb(cfg, binary, arch, out_dir) -> Path`.
- Feed: `feed(key, version, url, files, out) -> Path`, `feed_key(repo)`.
- Names: `<Name>-v<version>-<platform>.<ext>` with platform `macos-x86_64|aarch64`, `windows-x64|arm64` (+ `-setup.exe`), `linux-x86_64|aarch64`; the .deb as Debian names it, `<bin>_<version>_<amd64|arm64>.deb`.
