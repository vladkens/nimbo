# Model keys: keys while held and several hotkeys

Status: approved with the person's answers (2026-10-31), cut down to a working macOS demo first; Windows, X11 and Wayland are later tasks on the same API.

Goal: a demo on macOS where the person tries both ways to pick a dictation model from the hotkey. **Style 1, keys while held:** while a hotkey is held (fn alone, ⌥Space, right ⌥…), a configured key (Z, X, 1, ⇧Z, F5: any key, with or without modifiers) comes as `Edge::Key` and is taken from every app (its press, repeats and release), so a fast fn-Z can't reach the app in front. **Style 2, several hotkeys:** each model has its own hotkey (F1 / F2, fn+1 / fn+2, ⌥Space…), and each edge says which. Both can be configured at once, with no extra rules. The person, 2026-10-31: "I asked for a demo of this behaviour; the questions were too complex."

Today (main at 9ff1555): one hotkey per app. `Hotkeys::set(&str)` parses and arms one `Hotkey`; `Edge::{Down{at,repeat}, Up{at}, Escape, Aborted}` carry no index; macOS keeps one chord in `Shared::chord` (an `AtomicU64`) with one `chord_down`, Carbon's `CHORD_ID = 1` and `ESCAPE_ID = 2`; Windows one `RegisterHotKey`, X11 one grab, the portal one shortcut `"hotkey"`.

## The person's answers (2026-10-31)

1. Any shortcut can be bound (F1/F2, fn+1/fn+2, ⌥Space with Z…): every form below, no restriction for the demo.
2. Both styles at the same time (several hotkeys and keys while held): allowed, no extra rules.
3. One model key per dictation: after the first `Edge::Key` during a held hotkey, further keys are ignored until that dictation ends. Decided: nimbo delivers every key press while a hotkey is held (and takes it from the app in front); the app keeps the first after `Down` and ignores the rest until `Up` or `Aborted`, written in `Edge::Key`'s doc and done so by `examples/hotkeys.rs`. No hold-vs-latch logic in nimbo.
4. Keys are any key, alone or with modifiers; the recorder records them so.
5. Wayland: permanent portal shortcuts for keys are fine (later task).
6. Keys with a lone right ⌥ / ⌘ / ⇧ hotkey are allowed, with a warning the app shows (`Status::keys_error`), no refusal.

## Decisions

### The API

- **One call:** `Hotkeys::set(&mut self, hotkeys: &[Hotkey], keys: &[Hotkey]) -> Result<(), String>` replaces `set(&str)`. Keys reuse `Hotkey` (only its `Shortcut` form: a key with or without modifiers), so an app stores both as text, parses both with `Hotkey::parse` and records both with the same recorder. Refused, each alone (the rest are taken): more than `hotkey::MAX` = 8 of either, a duplicate, a key that is a modifier alone, a key on a chord hotkey's own key (its repeats). The `Err` names the first problem; `set(&[], &[])` clears.
- **Each hotkey on its own:** one the OS refuses (another app has F2) leaves the others armed; its error is its slot's (`Status::slots[i].error`).
- **Idempotent, slot by slot:** wavo-app calls `set` on every settings update. The portable `Hotkeys` diffs the lists (a pure function, tested) and hands the platform only what changed: `imp.set_slot(i, Option<Hotkey>) -> Result<(), String>` per changed or removed slot, `imp.set_keys(&[Hotkey])` when the keys changed. An unchanged slot is untouched (its held bit, its owed release, its Carbon registration stay) except a refused one, which is tried again. So a same-list `set` while fn is held keeps the press going. `pause` clears every slot and the keys, and arms them again after.
- **Edges say which:** `Edge::Down { which, at, repeat }`, `Edge::Up { which, at }`, `Edge::Aborted { which }` (`which`: the hotkey's index in `set`), `Edge::Key { index, at }` (`index`: the key's index in `keys`; the app maps it to a model), `Edge::Escape` unchanged. `Edge` stays exhaustive, written in its doc: an app's hotkey state machine should fail to build on a new edge.
- **Keys while held:** while any hotkey is held, a fresh press of a configured key is taken and comes as `Edge::Key`; its repeats and release are taken too and told by nothing, also when the hotkey went up first. A key already down before the hotkey stays the app's. A fresh press while no hotkey is held passes and clears any release still owed (a lost hotkey release never makes a key stay taken). Paused, nothing is taken.
- **How a key matches:** by its place, and its modifiers equal either the event's or the event's minus the held hotkeys' own (⌥Space held: ⌥Z matches `z`; fn held: fn-⇧Z matches `shift+z`); fn never counts in a key. The first match in the list wins. Repeats and releases by place.
- **A taken key closes the chord window:** after fn-Z (or right-⌥ Z), a later key while the modifier is still held is typing (passes), never the user's chord, so it doesn't abort.
- **A chord sharing a lone hotkey's key:** fn alone with fn+1, or right ⌥ alone with ⌥Space: a press of the chord while the lone key is held aborts the lone hotkey and is the chord's press: two hits, `Aborted { which: lone }` then `Down { which: chord }`.
- **Keys with a lone ⌥ / ⌘ / ⇧ hotkey:** taken as with any hotkey; `Status::keys_error` warns ("while Right ⌥ is held the keys are taken: they may conflict with typing"). fn alone has no warning.
- **fn as a chord modifier (macOS):** `fn+1` parses as a `Hotkey` with `Modifiers::FN` (`fn`, `globe`), written back `fn+1`, labelled `fn 1` (`fn ⌥1`). Refused with keys whose events carry the fn flag anyway (F1–F20, arrows, Home, End, Page Up/Down, Forward Delete). Windows and Linux refuse it in that slot. In-app shortcuts (`Shortcut::parse`) don't take `fn`; `Shortcut::matches` ignores `FN`.
- **Capability:** `hotkey::keys_while_held() -> bool`: macOS true; Windows and Linux false until their tasks. Until then they arm slot 0 only (the others' error "one hotkey here for now") and take no keys (`keys_error` says so), so the crate builds and passes its checks on all three.
- **Status:** `slots: Vec<Slot>`, `Slot { hotkey, error, fallback, fallback_error }`, replacing `hotkey`, `error`, `fallback_error`. `fallback: bool` stays, meaning every armed slot has a working fallback (wavo-app's `dead = listener == Failed && !fallback` stays right). New `keys: Vec<Hotkey>` (taken), `keys_error: Option<String>`, computed in `status()` as `escape_error` is: a key left out by `set`, no active tap or Secure Input on ("keys while held need the event tap: Accessibility access"), the lone-modifier warning, the platform can't. `Counts::keys`. `Status`, `Counts` and `Slot` become `#[non_exhaustive]`.
- **One "owed key" rule:** "a fresh press claimed is ours until its release; its repeats and release are swallowed; a repeat of a press the app saw stays the app's; a fresh press settles who owns it" exists in macOS `owned()` and Windows `Lone::escape`. It moves to `src/hotkey.rs` as a pure `fn owe(owed: bool, kind, repeat: bool, ours: bool) -> (bool, Take)` (`Take::{Pass, Swallow, Claim}`), unit-tested once; macOS uses it now, Windows' `Lone::escape` moves onto it in task 1 (mechanical).

/// Exhaustive on purpose: a hotkey state machine should fail to build on a new edge.

  Escape,
  Aborted { which: usize },
}

### macOS: the event tap (with Accessibility)

- **Slots:** `chords: [AtomicU64; MAX]` and `count: AtomicU8` replace `chord`, each encoded as today (`SET`, `LONE`, key code, flags) plus an `FN` bit. A changed slot is stored 0 (its held bit dropped), then its new value; `count` is stored with Release, read with Acquire. No lock, no allocation in the callback.
- **Keys:** `keys: [AtomicU64; MAX]` (place and modifier flags) with `keys_count: AtomicU8`, since `kVK_ANSI_A` is 0 and can't mark "none"; `keys_owed: AtomicU8`, a bit per key whose press was taken.
- **Held state:** `chord_down` becomes `down: AtomicU8`, a bit per slot (an owed chord release or a lone key held), and `since: [AtomicU64; MAX]`, each slot's press time.
- **Stale bits:** (a) Carbon's release of chord slot i (the route thread) clears bit i unless `since[i]` is newer than Carbon's press (a missed tap release while the tap was disabled); (b) a held lone slot is released by the next event without its flag (today's rule); (c) a fresh press of a key with nothing held clears its owed bit and passes; (d) a fresh press of a chord's own key settles its bit, as `owned()` does.
- **`judge`'s order:** (1) each lone slot's own `flagsChanged`; (2) reconcile: a held lone slot whose flag is missing is released (`Up`, or `Aborted` on Escape's press) before anything reads `down`; (3) keys through `owe`: owed repeat or release swallowed; a fresh press with any slot held claimed, `Key`, every lone slot's chord window closed; otherwise passes and clears its bit; (4) chord slots through `owe` on their bits, a chord on a held lone slot's modifier aborting it too (two hits); (5) the lone slots' abort (another key within `CHORD_WINDOW`); (6) Escape. (2) before (3) keeps a missed fn release from taking Z; (3) before (5) keeps fn-Z from aborting fn.
- **Two hits:** `Verdict::{Pass, Tell([Option<Hit>; 2]), Swallow([Option<Hit>; 2])}`; no allocation.
- **fn chords:** compared with `MODIFIERS | MaskSecondaryFn` when the slot has `FN`, else `MODIFIERS` as today (F1 still matches when the F-row event carries fn).
- **The hotkey thread:** `Hit::{Down{which,repeat}, Up{which}, Abort{which}, Key(index), Escape}`; `route` maps them to `Edge`; `Dedupe` keys its times by (kind, which); Carbon's repeat tracking is a bit per slot.

### macOS: Carbon, only as far as the demo needs

- **N chords:** one `RegisterEventHotKey` per chord slot, id `1 + which`; Escape moves to `0x100`; the handler maps the id back. A refused slot is that slot's `fallback_error`; the others stay. fn alone, other modifiers alone and fn chords have none, as today.
- **No leaked registration:** `set_slot` unregisters that slot's ref before registering anew; a removed slot, `pause` and `Drop` unregister theirs.
- **No keys through Carbon now:** without the tap (no Accessibility, Secure Input) hotkeys still work through Carbon, keys don't, and `keys_error` says so. Keys through Carbon (registered while a chord is held, its race, `CGEventSourceKeyState` for a lost release) are a later task.

### The recorder

- `shortcut_behavior(id, value, clear, lone: bool)` becomes `shortcut_behavior(id, value, clear, mode: Record)`, `Record::{Chords, ChordsOrModifier, Key}`, one loop and one drawing. `Record::Key` records the next key that isn't a modifier, by place, with the modifiers held except fn (Z, ⇧Z, ⌥1, F5, Space); a lone modifier is ignored; Escape alone stops and Backspace or Delete alone clear, as for hotkeys (those three are set as text if wanted). Texts: "Record Key", "Type a key…", the same 160 width.
- **Breaking (review, 2026-10-31):** `Response` gains `pub recording: bool` (a shortcut recorder is recording), so an app pauses its hotkeys only while one records; a struct literal of `Response` outside the crate no longer builds (none in this repository).
- `Ui::shortcut_key(&mut self, value: &mut Option<Hotkey>)` draws it with `Record::Key`; `Ui::shortcut` picks `ChordsOrModifier` where `modifier_alone()`, else `Chords`, as today.
- **fn from the key event (macOS):** done otherwise (review, 2026-10-31): in-app key and pointer modifiers carry no `FN` (so `mods.is_empty()` checks hold while Globe is down); the recorder tracks fn from its own `Event::Modifier` and adds `FN` to the chord, except with a key that carries it anyway (`keys::carries_fn`, Help/Insert included). Tests press fn as `Event::Modifier { key: Code::Fn, .. }`.
- Recorded by place, labelled as a US keyboard has them, as today; written in the recorder's doc.
