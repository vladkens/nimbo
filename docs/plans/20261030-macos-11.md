# macOS 11 as the minimum, with no setting in the app

Goal: an app built on nimbo sets no `MACOSX_DEPLOYMENT_TARGET`: nimbo's minimum drops from macOS 14 to macOS 11, rustc's default for `aarch64-apple-darwin` (`rustc --print deployment-target`), and every API newer than 11 gets a run-time fallback or reports itself unavailable. Decided by the person on 2026-10-30 ("nimbo must not enforce anything on apps"; ~200 lines are fine; agents.md's "macOS 14 is the minimum … with no fallbacks for older systems" is replaced). Based on the research of 2026-10-30 (`macos-min-research.md` in the session's scratchpad), each point checked against main at 452b924 below, and revised after an independent review of this plan (2026-10-30). The same PR also carries a queued CI change: the `build` job runs on release PRs.

## Decisions

- Minimum: macOS 11 on Apple Silicon and on Intel, the one number in the docs. nimbo adds no guards for the 10.13/10.14 constants Intel imports (`NSPasteboardTypeFileURL`, `NSAppearanceNameDarkAqua`): below 11 is unsupported, and a bundle says 11 through shipo (follow-up below). A bare Intel binary claims rustc's 10.12 and fails in dyld on 10.12–10.13; that is out of support, not a bug.
- Fallback checks: `objc2::available!(macos = N)` (no new crate, folds away for apps that set a higher target), `respondsToSelector:` where nimbo already uses it. No C symbol newer than 11 is linked (the guard enforces it).
- Activation: one private `fn activate(mtm)` in `src/platform/macos/mod.rs` (its child modules `shell` and `app` reach it): `activate` on 14+, else `#[allow(deprecated)] activateIgnoringOtherApps(true)`.
- Display link: two paths in a new `src/platform/macos/link.rs`: `CADisplayLink` from the view on 14+ exactly as now, and a shared `CVDisplayLink` per display below 14, behind one `Link` type with what `view.rs` uses. Why not `CVDisplayLink` everywhere, which would be one path tested on every Mac:
  - Zed's GPUI (main 14b7b0e, 2026-10-30, `crates/gpui_macos/src/display_link.rs`) does the same split: `CVDisplayLink` only before 14, the system's display link on 14+.
  - `CVDisplayLink` is deprecated since 15: the main path on every current Mac would stand on it.
  - NSView's link follows the view's screen and honours `preferredFrameRateRange` (60–120 on ProMotion, lowered by the system as it likes); `CVDisplayLink` runs on its own thread at the display's rate, has to be pointed at the window's display by hand, and stops/starts instead of pausing. The 14+ path stays as measured (its pacing, 0 wakeups when still); the split costs ~15 lines over the code the fallback needs anyway.
  - Rejected for below 14: the existing `Wake` dispatch timer repeating at the refresh rate (~40 lines): frames not aligned to vsync drift against it and judder, and nimbo is judged on feel.
- The `CVDisplayLink` fallback is written from Apple's CoreVideo docs (`CVDisplayLink.h`) and the MIT `display-link` crate (BrainiumLLC/display-link 0.2.0, `src/macos/cvdisplaylink.rs`, a checkout in `3rd/display-link`; named in `link.rs`'s header with its license if code is taken from it). GPUI's Apache-2.0 code is not ported or copied; its module doc's crash lessons are cited as a reference in a comment, and followed: one link per display, created lazily and never released (`CVDisplayLinkStop` returns before its thread is done); the callback's context is the display id, not a pointer, and it touches only a static registry, so a late callback is harmless; each view has a coalescing `DATA_ADD` dispatch source on the main queue, resumed before it can be dropped; no CoreVideo call while holding the registry's lock.
- CoreVideo through `dlopen` of `/System/Library/Frameworks/CoreVideo.framework/CoreVideo` and `dlsym` (once, into a `OnceLock` table of the 7–8 functions), not `#[link]`: they are deprecated, and a strong import would kill launch in dyld on the macOS that drops them, even on 14+ where they are never called. A missing function (not expected on 11–13, where they ship) makes the fallback pace by `Wake` re-armed every 1/60 s while unpaused, logged once to stderr. No `objc2-core-video`: the crate count stays.
- The callback is an `unsafe extern "C" fn` that never panics: no `unwrap`, the registry's `Mutex` taken with `unwrap_or_else(PoisonError::into_inner)`, only `merge_data(1)` on the subscribers' sources.
- `Link` variants: `Link::Ca(Retained<CADisplayLink>)` and `Link::Cv(CvLink)`. The display id is looked up from `window.screen()` (`deviceDescription()["NSScreenNumber"]`, the main display's when the window has none) each time `set_paused(false)` subscribes, not when the link is made; `screen_changed` moves only a running subscription. `impl Drop for CvLink`: unsubscribe, then cancel the source.
- `NIMBO_CVDISPLAYLINK` (kept, the coordinator's decision): set, the fallback runs on 14+ too, so its pacing is checked on macOS 27 without an old VM; read once when a link is made, documented in `link.rs`'s doc beside `NIMBO_TRACE`. Two lines.
- `Wake` (`view.rs:1044-1074`) and `refresh` (`view.rs:1037-1042`) move to `link.rs` with `display_link()`, so `view.rs` ends clearly under 800 code lines.
- Section headers below 14: a disabled item with the title and no action (what Windows, Linux and muda do); `describe` reports `header` for a section header on 14+ and, below, for an item with no action and no submenu (no other item is made that way).
- Launch at login below 13: `available()` is `Err("launch at login needs macOS 13 or later")` before the bundle check, so `state` and `set` fail with it; `open_settings` does nothing below 13 (it isn't gated by `available()` today).
- Guard: `scripts/macos-min.py` (Python, `uv run`), run by `make check` only (no macOS CI job, the coordinator's decision); off macOS it prints a line and exits 0, so the Ubuntu CI job's `make check` passes through it. It builds the examples with `MACOSX_DEPLOYMENT_TARGET` removed from its environment and no `--config` (so a deployment target that comes back through `.cargo/config.toml` fails it), then:
  1. reads each example's `LC_BUILD_VERSION` minos (`otool -l`) and fails unless it is `11.0` (`MIN`); on a non-arm64 host (rustc's x86_64 default is 10.12) it skips this step with a line saying so and runs the rest;
  2. takes the framework imports of every example (`nm -mu`, all but `libSystem`, `libobjc`, `libc++`) and the unmangled undefined symbols of `libnimbo-*.rlib` (`nm -u`: nimbo's own `extern`s, also those no example links, such as `hardware.rs`'s CoreAudio and IOKit), the paths from `cargo build --message-format=json`;
  3. writes one Objective-C file that imports the umbrella header of each framework nimbo links (Cocoa, Carbon, CoreText, IOSurface, QuartzCore, ServiceManagement, CoreAudio, `IOKit/IOKitLib.h`, ApplicationServices, CoreServices) plus `<dispatch/dispatch.h>`, `<objc/runtime.h>`, `<pthread.h>`, `<dlfcn.h>`, `<sys/sysctl.h>`, and takes `&symbol` of each (`[Name class]` for an `_OBJC_CLASS_$_Name`, which objc2 doesn't emit today), and runs `xcrun clang -fsyntax-only -x objective-c -mmacosx-version-min=11.0 -Werror=unguarded-availability -ferror-limit=0` on it;
  4. fails on every clang error, naming the symbol and the binaries importing it ("is only available on macOS X or newer", "is unavailable", anything else), except an undeclared identifier that is: listed in the SDK's `usr/lib/system/*.tbd` or `usr/lib/libobjc.A.tbd`; one of objc2's statics (`__CLASS_`, `__IVAR_OFFSET_`, `__DROP_FLAG_OFFSET_` after the leading underscore); compiler-rt's (`__*`); or std's `rust_*`.
  SDK availability comes from the headers through clang, no allowlist to keep. It doesn't see selectors (objc2 sends them at run time): those stay with review.
- Budget: `platform/macos` 2500 → 2700 (expected ~170–200 new lines: `link.rs`'s fallback and dlsym table ~150–170, the view and delegate glue ~15, `activate` ~10), recorded in the PR with the measured number; `app/macos` (1708/1800) takes the menu and autostart fallbacks (~15 lines) without a raise.
- Testing, light by the person's word (2026-10-30): `make check` (with the guard) and `make test` at the end of every task; one quick run on the macOS 27 VM because the change touches the 14+ display link and activation; a smoke check on a macOS 12 VM once the vm project has one, which doesn't block the merge. No `ax-check.py` and no pace runs on old systems; a broken fallback there comes back as a bug report.
- readme.md stays out of this PR (the person's standing rule: no readme edits in feature PRs); its line 56 is a follow-up for the docs/release PR.
- Commits only when the person asks (agents.md, Workflow). release-check (vladkens/actions, #9 merged) fails a release while `docs/plans/` has a finished plan outside `completed/`, or a `completed/*.md` without `Done: yyyy-mm-dd` as the first line under its title and a `## Result` heading, so this plan ends that way (task 7).

## Risks

- The `CVDisplayLink` path is checked only by the 27 run through the switch until a macOS 12 guest exists: a difference that shows only on 12 (the main queue's draining in a nested run loop there, the first callback's delay after a start) would come as a bug report, as the person accepts.
- Stopping and starting a display's link every time the view goes idle (each key press ends in a pause) costs a CoreVideo start per burst of frames; GPUI starts and stops on subscription the same way. If the 27 run with the switch shows a late first frame, keep the link running for a short grace after the last subscriber leaves.
- The guard sees C symbols only; a newer selector or class used without a check still crashes on 12–13 at first use. Review and the smoke check are what catch those.
- `stop` (`view.rs:561-570`) still skips `invalidate` when the state is busy (the `Ca` link then keeps the view alive); not changed here, noted for a follow-up if it shows.
- `available!` with no deployment target checks at run time; an app that sets a higher target folds it at compile time and drops the fallback code, which is the intended behaviour.
