# Updater

Done: 2026-10-28

Goal: an app built on nimbo updates itself in place, as Sparkle does, with no window of nimbo's: it checks a signed feed, downloads its file over the OS's HTTP, checks the file's SHA-512 against the feed, unpacks it with the system's tools, swaps it in, and relaunches. The new process waits for the old one to let its instance go. nimbo returns states and errors; the app's menu, setting and schedule show them. Asked by wavo-app, approved 2026-10-26 (`~/Code/notes/nimbo/readme.md`, roadmap item 0). Plan reviewed 2026-10-27; its findings are folded in below.

## Decisions

- **API: `src/update.rs`.** Blocking functions the app runs on a thread of its own and reports back with `Proxy::post`:
  - `check(&Feed, current: &str) -> io::Result<Option<Release>>`;
  - `download(&Release) -> io::Result<Staged>`, which fetches, verifies and unpacks;
  - `install(Staged) -> io::Result<()>`, which swaps and relaunches; the app quits after `Ok`.

  `Feed { url, key: &str }` holds the feed's URL and the base64 public key from a const. Errors are `io::Error` (`PermissionDenied`, `Unsupported`, `InvalidData` for a bad signature or hash), and nothing opens by itself.
- **Feed: one signed JSON file.** A release's CI writes `update.json` and `update.json.sig` (ed25519 over the JSON's bytes, base64) and hosts them anywhere. On GitHub they are release assets, so `https://github.com/<o>/<r>/releases/latest/download/update.json` serves without the GitHub API.
  - Shape: `{"version": "1.2.0", "notes": "…", "platforms": {"macos-aarch64": {"url": "…", "sha512": "<hex>"}, …}}`; keys are `<OS>-<ARCH>` from `std::env::consts`.
  - The signature is checked before the JSON is parsed. A minimal reader parses objects, strings and numbers, and a tiny base64 decoder reads the key and signature.
  - Versions compare by numeric dot parts, a pre-release below its release; a version that isn't newer than the running one is no update (no downgrade, no replay).
  - Feed and file URLs must be https, except on loopback (the tests and the VM runs).
- **Signature and hash: `ed25519-compact` 2.6.0** (2026-09-25) with `default-features = false`: no dependencies of its own, crate count 20 → 21. Security.framework has no Ed25519, CNG no EdDSA, and Linux would need libcrypto loaded at run time; a port would cost ~300 lines. Its `sha512::Hash` hashes the download as it streams, checked against the feed before anything is unpacked. Signing is two `openssl` 3 commands in the module docs (`genpkey -algorithm ed25519`, `pkeyutl -sign -rawin`); CI wiring belongs to the app.
- **HTTP: `get(url: &str, to: &Path) -> io::Result<()>`**, a new contract in `src/platform/mod.rs`, in `src/platform/<os>/app/http.rs`. It blocks, follows redirects (GitHub sends assets to another host), and treats a status other than 2xx as an error. Progress is left out at first.
  - macOS: `NSURLSession` `downloadTaskWithURL`, the completion handler moving the file; objc2-foundation features only.
  - Windows: WinHTTP with `WINHTTP_ACCESS_TYPE_AUTOMATIC_PROXY`; windows-sys `Win32_Networking_WinHttp`.
  - Linux: `libcurl.so.4` loaded at run time through `dl.rs`, the easy API only (`curl_easy_init/setopt/perform/getinfo/cleanup`, a write callback into the file). GIO over gvfs needs a session bus, gvfs-backends and glib-networking, missing on KDE, minimal installs and CI.
- **Archive contract.** The macOS `.zip` (`ditto -c -k --keepParent`) holds exactly one top-level `.app`, the Windows `.zip` exactly one top-level folder, whatever their names; anything else is `InvalidData`. Before the swap the new bundle's id (macOS) or the folder's exe name (Windows) must match the running app.
- **Target and checks before downloading.** Each fails early, before a byte is fetched:
  - macOS: the running bundle from `uninstall`'s rules; a translocated one (`/AppTranslocation/` in its path) is an error.
  - Windows: the folder holding the running exe, whose name must match the archive's top-level folder (checked after unpacking), so a cargo `target\` build never matches: `Unsupported`.
  - Linux: `$APPIMAGE`; without it `Unsupported`.
  - The target's parent must be writable (`/Applications` for a standard user, Program Files, `/opt`): `PermissionDenied`.
- **Unpack and swap.** The download goes into a fresh 0700 folder made with `create_dir` (failing if it exists); the package is staged beside the target so the final rename stays on one volume. Tools run by absolute path, never from `PATH`:

  | OS | unpacked with | swap |
  |---|---|---|
  | macOS | `/usr/bin/ditto -x -k` into `<dir>/.<name>.app.new/` | the new bundle must meet the running one's designated requirement (`/usr/bin/codesign -v -R=<req>`), else refused; the running bundle is renamed to `.<name>.app.old`, the new one takes its name |
  | Windows | `%SystemRoot%\System32\tar.exe -xf` into `<exe dir>\.update\` | each file is renamed to `<file>.old` where one exists, then the new file is moved in |
  | Linux | none | `chmod +x`, then the new file is renamed over `$APPIMAGE` |

  - Any failure after the first rename undoes every rename made so far, including a failed relaunch.
  - Process calls (`ditto`, `codesign`, `tar`, the relaunch) live in `src/platform/<os>/app/update.rs`; the path logic stays in `src/update.rs` with an `Os` parameter, as `uninstall::app_of` does.
- **Relaunch, tied to the instance.** `install` starts the new app with `NIMBO_RELAUNCH=<old pid>:<instance dir hash>`:
  - macOS: `NSWorkspace openApplicationAtURL` with an `NSWorkspaceOpenConfiguration` (`environment`, `createsNewApplicationInstance`), so launchd, not the old process, is the new one's responsible process for TCC.
  - Windows: the exe spawned. Linux: `$APPIMAGE` spawned.
  - In the new process `instance::claim_in` calls an inner `claim_until(dir, wait)`: when the hash matches its own instance dir, it waits until the old pid exits or the lock frees, whichever comes first, with a cap of 60 s. A value with another hash (a child of the new app inheriting it, another nimbo app) is ignored.
  - Every launch removes `.old` leftovers beside the target with `uninstall::remove`, not only a relaunched one, as a slow exit can outlast its 5 s retry.
- **App requirement, not nimbo's task.** On macOS updates keep the microphone and Accessibility grants only when every release is signed with one stable identity: TCC keys an ad-hoc app by its cdhash. wavo-app's CI signs ad hoc today (wavo-app `scripts/bundle.py:16`), so it needs a stable identity before it ships the updater; the designated-requirement check refuses mismatches anyway.
- **Budgets.**
  - A new `update` budget of 400 lines; the BUDGETS key alone matches `module()`, no `PARTS` change.
  - `app/shared` (1495/1500) → 1600 for `claim_until` and the wait in instance.rs, which use its private `LOCK` and `imp`.
  - `app/macos` (1564/1600) → 1700 and `app/linux` (2090/2100) → 2200 for `http.rs` and `update.rs`; `app/windows` (1601/1700) → 1800 only if they go over. The http files count in `app/<os>`, so `platform/windows` (2188/2200) is untouched.
  - Write the code tight before raising anything further.

## Result

`nimbo::update` checks a signed feed (`check`), downloads, verifies and unpacks a release beside the app (`download`) and swaps it in and relaunches it (`install`), on macOS, Windows and Linux over the OS's HTTP (NSURLSession, WinHTTP, libcurl loaded at run time); the relaunched app waits in `instance::claim_in` for the old one and removes what it left. Checked end to end in the macOS, Windows and Ubuntu VMs. After review: an undo retries busy renames for 5 s and, failing, keeps the staged folder and says where the files are; every launch also removes staging folders of processes that have ended; libcurl follows at most 10 redirects, to https only (http too from loopback), and is initialised once; the macOS relaunch gives up after 35 s and undoes the swap; on Windows a build's folder is refused once unpacked, as only the archive names the app's folder. The relaunched app's 60 s cap stays: a reused pid or an old app that never quits would otherwise keep it waiting unseen. One crate added (`ed25519-compact`, 20 → 21); budgets `update` 500 (new), `app/macos` 1600 → 1700, `app/linux` 2100 → 2200.
