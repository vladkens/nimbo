# App glue from wavo-app

Done: 2026-10-26

wavo-app, the first app on nimbo, wrote platform glue any tray or desktop app needs again: one instance with commands to it, a paste into another app that gives the clipboard back, an uninstall that leaves nothing behind. The person asked to move what isn't Wavo-specific into nimbo, so the next app gets it ready (2026-10-26); wavo-app's agent listed it from the consumer's side. Reviewed against nimbo `d214748` and wavo-app `f0101c2` (2026-10-26) and revised. wavo-app adopts each piece after it's in main.

## Decisions

- **Ported, not rewritten.** The code is wavo-app's (same author, MIT), tested there on macOS, Windows, Ubuntu GNOME and Kubuntu; ported with its tests, shaped to nimbo's seams. No new crates: no `libc` (std, `io::ErrorKind`, `extern "C"`), no `thiserror` (a hand-written `Display`), no logging (nimbo has no logger).
- **By `AppInfo`, or by a directory.** What's per app hangs off `AppInfo::id` and `paths`; a public `*_in(dir)` variant takes a directory, as wavo-app keys its instance by its home (`WAVO_HOME` keeps dev runs and tests apart).
- **Stays in wavo-app:** the microphone list and its permission, the per-OS default hotkey, the QoS hint for a transfer, removing the app's own data and models.
- **Not in this PR:** the build helper for icons (a `nimbo-build` crate with no dependencies: its own inflate for real PNGs, the `.ico`, a `.res` linked directly; a workspace member with its own publishing) — its own PR later, in the backlog. Packaging stays a script per app.
- **Where code counts:** the new modules (`instance`, `paste`, `uninstall`) count against `app/shared` (mapped in `PARTS`). Budgets: app/shared 1000 → 1400 (the paste's 143 lines did not fit in 1300), app/windows 1500 → 1600, app/linux 2000 → 2100, app/macos 1600 → 1700, each raised when a task needs it.

## Tasks (in this order)

- [x] 1. **Small pieces**:
  - `paths::downloads()`: new code (wavo-app only had `$HOME/Downloads`): `XDG_DOWNLOAD_DIR` from `user-dirs.dirs` on Linux (a localized folder, or none), the Known Folder on Windows (in app/windows), `~/Downloads` on macOS; `paths`' doc no longer says "only the environment is read";
  - the shortcut recorder doesn't record a lone modifier where the platform can't grab one (Linux): `hotkey::modifier_alone()`; and `hotkey::start_asks()` (the listener's start shows the desktop's dialog: the GlobalShortcuts portal), which replaces the planned public `wayland()`;
  - `nimbo::attach_console()` on Windows (a GUI-subsystem exe run from a console prints there), from wavo-app's `src/main.rs`;
  - `tray::short(name, max)`: a menu label shortened at a word, inside its brackets (`System Default (MacBook Pro…)`), from wavo-app's `src/menu.rs`.
- [x] 2. **One instance** (`src/instance.rs`; the Unix socket in one file shared by `platform/macos/app` and `platform/linux/app`, the pipe in `platform/windows/app`), from wavo-app's `src/ctl.rs` and `src/cli.rs:244-264`:
  - `instance::claim(&AppInfo)` / `claim_in(dir) -> Claim { Primary(Instance), Running }`, before the loop; inside `nimbo::app`'s start, `main.serve(instance, |main, cmd| …)` keeps the instance (and its lock) in the shell's state until the loop ends; a bare "open" also runs `on_reopen`, so one handler covers a Dock reopen and a second launch.
  - `instance::send(&AppInfo, &str)`, `quit_and_wait(&AppInfo, timeout)`; `Command { name, token }` in a defined line format (the pipe's line limit raised for tokens).
  - Unix: the socket under `$XDG_RUNTIME_DIR` (Linux) or `$TMPDIR` (macOS), 0600, within `sun_path`'s 104 bytes; a dead instance's socket replaced. Windows: the pipe for this user only (wavo-app's SDDL, first instance), the sender's `AllowSetForegroundWindow`; windows-sys features added (Security_Authorization, Storage_FileSystem, System_Pipes, System_IO, System_Console).
  - The activation token: a command carries the sender's `XDG_ACTIVATION_TOKEN` / `DESKTOP_STARTUP_ID`; the shell keeps it while the handler runs, and both `Main::open` (shown) and `Window::front` use it (`gtk_window_set_startup_id` before the first show or `gtk_window_present`); the launcher entry gets `StartupNotify=true` (`desktop.rs`) so GLib hands a launch its token.
  - The `tray` example uses it (never under `--shot`). Tests: claim twice, send and receive, a dead socket replaced, quit and wait. The pipe needs a Windows check (VM) before the PR.
- [x] 3. **Uninstall** (`src/uninstall.rs`), from wavo-app's `src/cli.rs:60-234`: `uninstall::system(&AppInfo) -> Vec<Step>` (a label and its result) undoes what nimbo set up: launch at login, the launcher entry (Linux), the portal token (`config_dir/remote-desktop.token`), macOS permissions (`tccutil reset All <id>`) and defaults (`defaults delete`, the leftover plist); `uninstall::app_path()` (the `.app` or AppImage the exe runs from), `outermost(dirs)`, and `uninstall::remove(path)` with retries on Windows' sharing/lock/access errors and macOS' not-empty. The app removes its own data, after `instance::quit_and_wait`. Tests in temp dirs.
- [x] 4. **The paste** (`src/paste.rs`), from wavo-app's `src/app.rs:948-1181`:
  - `paste::text(text, Paste { restore, target }) -> Result<(), NotPasted>` on the main thread: the text as an offer, the paste shortcut (⌘V; Ctrl+V; Ctrl+Shift+V into a Linux terminal, known by `/proc` comm), the clipboard given back after the offer is read or after a cap, only while it still holds the text; refused when the app in focus is unknown (unless the platform hides it: Wayland), the focus moved from `target`, or it's a password field (Secure Input); the Accessibility check before posting.
  - A pending restore runs at quit (an internal hook in `shell::finish`, not the app's `on_quit`).
  - Wayland's first paste waits for the portal's dialog (nimbo waits up to 60 s): the doc says so, and an off-main caller waits longer (a public constant).
  - Tests through an internal seam (snapshot, offer, holds, restore, post, focus, timers) with a fake; `examples/tray.rs`'s paste becomes `paste::text`.
- [x] 5. **Docs**: the readme's features and a short section on packaging an app (what every app needs that wavo-app's `bundle.py` and `dist.py` do: the `.app` with `Info.plist` and a stable signing identity so macOS keeps permissions, the Windows zip with the C runtime linked in, the AppImage with its `.desktop`); AGENTS.md's toolkit lines; budgets recorded; the plan moved to completed.

## Result

nimbo has the glue a tray or desktop app needs, ported from wavo-app with its tests: `paths::downloads`, `hotkey::modifier_alone` / `start_asks`, `attach_console`, `tray::short`; one instance with commands from a second launch and the Linux activation token (`instance`); an uninstall that undoes what nimbo set up (`uninstall`); a paste that gives the clipboard back (`paste`, `focus::hidden`). The readme has them and a short part on packaging an app. Budgets raised: app/shared 1000 → 1400, app/windows 1500 → 1600, app/linux 2000 → 2100. Left: the Windows pipe and the Linux activation token checked in VMs before the merge; the `nimbo-build` crate stays in the backlog.
