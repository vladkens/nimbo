# A proper macOS menu bar and the app's commands

On macOS the bar was a stub: one app menu with Close Window and Quit, and no way for an app to add
anything. The goal: the bar of a proper Mac app by default, and SwiftUI's `.commands` for the app's
own menus and items.

## 1. The standard bar
- [x] The app menu (About, Settings… when the app has settings, Services, Hide, Hide Others, Show
  All, Quit), File (Close Window), Edit (Undo, Redo, Cut, Copy, Paste, Select All), View (Enter
  Full Screen), Window (Minimize, Zoom, Bring All to Front) and Help, on AppKit's own selectors
- [x] `servicesMenu`, `windowsMenu` and `helpMenu` set, so AppKit fills them
- [x] The labels through `t!`, in nimbo's catalogs (`make i18n`) with every language translated
- [x] Edit's items reach nimbo's fields: the view answers `copy:` and the rest with the command its
  key would run, delivered as the key's is; the view is offered the key first, so the menu runs
  only a key nobody used
- [x] Edit's items disable when nothing focused binds their command (`validateMenuItem:`)

## 2. The app's commands
- [x] `Commands<A>`: `menu` (SwiftUI's `CommandMenu`), `before` / `after` / `replacing` a
  `CommandGroupPlacement` (`CommandGroup`), `settings` (the `Settings` scene's item), over
  `Menu<A>` / `Item<A>`
- [x] `Main::set_commands(&Commands<A>, f)`: the bar rebuilt, `f` runs with the chosen action
- [x] macOS only; the platform contract says so, Windows and Linux bind keys in `App::keymap`
- [x] A gallery row and `docs/api.md`
