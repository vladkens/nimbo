# Layers, headless controls, features, a stable API

The goal: after 1.0 no app breaks. The crate is three layers an app picks from: the core (OS and renderer), headless behaviour to build a design system on, and the ready one that looks like System Settings. A build compiles only the features it turns on, and no lower module uses a higher one.

Decided by three agents' reports (layers, features, the 1.0 API) and their votes on the merged plan, 2026-11-18, on a09e33f:

- One crate: modules and cargo features, no workspace. The API is methods on `Ui`, which another crate couldn't add, and crates would freeze today's `pub(crate)` items as public API.
- A few large PRs, one idea each; every one is checked by building and testing wavo-app and awake against its branch.
- 0.x releases first; 1.0 once wavo-app and awake have run on the final shape and `examples/custom-look.rs` builds.
- `Color` stays an alias of `[f32; 4]`, documented.
- Defaults: `styled` only. Adding a default later breaks nothing; removing one does.

## 3. The core without the theme, the styled layer on public API
Decided by two design reports and my vote, 2026-11-23: most reaches are core or headless code living in styled files, so they move down; what is left gets a few small general primitives. After it the baseline has no `layer` and no `private` lines.
- [ ] Core code out of styled files: `lazy` and `image` into the core; a menu's open state and the native context menu into the core (`menu_open`, `set_menu_open`, `native_menus`, `native_menu`); `Menu::tagged` public
- [ ] The behaviours into `ui/behavior/` (headless): split, pick, slider, shortcut, menu item, dialog, search, pop-up, toggle, the list's keys and presses (`list_behavior`), the scroll bars; `field_text` with FieldStyle and `text_input`
- [x] Theme out of the core: a value store kept across frames (`environment` / `set_environment`, one mechanism with `slot`); `theme()`, `set_theme`, `follow_system` and `controls_theme` in theme.rs, the theme the app set or the system's for the appearance; the focus ring from the theme each frame unless the app set one; `take_helps` in the core, the tooltips drawn by the styled layer after the view; the scroll area into headless beside its bars (menus scroll in it), its thumbs' look an environment value (`ScrollIndicatorStyle`)
- [x] Small public primitives for the rest: `take_help`, `disabled_scope` (sets the scope, so a part enables itself), `with_key` (the next element's id without the pointer), `stack_axis`, `stack_len`, `element_count`, the a11y name helpers (`a11y_named`, `a11y_row`, `form_names`), `unified_toolbar` (the title bar's toolbar request), `request_frame`; the edit menu into the styled layer; `response`, `partial`, `detached`, `edge_fade` not needed
- [ ] The `private` rule also catches the core's crate-private fields and types (`ui.next_id`, `Node`, `Flow`), a crate-private function called after a `use`, and names a `pub fn` elsewhere shares; child-module paths and globs in the layer rule
- [ ] The baseline's `layer` and `private` lines gone
- A scoped `.environment(v)` modifier waits for the styles (4), which need it; ControlSize and disabled keep their scopes until then
