# Layers, headless controls, features, a stable API

The goal: after 1.0 no app breaks. The crate is three layers an app picks from: the core (OS and renderer), headless behaviour to build a design system on, and the ready one that looks like System Settings. A build compiles only the features it turns on, and no lower module uses a higher one.

Decided by three agents' reports (layers, features, the 1.0 API) and their votes on the merged plan, 2026-11-18, on a09e33f:

- One crate: modules and cargo features, no workspace. The API is methods on `Ui`, which another crate couldn't add, and crates would freeze today's `pub(crate)` items as public API.
- A few large PRs, one idea each; every one is checked by building and testing wavo-app and awake against its branch.
- 0.x releases first; 1.0 once wavo-app and awake have run on the final shape and `examples/custom-look.rs` builds.
- `Color` stays an alias of `[f32; 4]`, documented.
- Defaults: `styled` only. Adding a default later breaks nothing; removing one does.

## 3. The core without the theme, the styled layer on public API
Decided by two design reports and my vote, 2026-11-23: most reaches are core or headless code living in styled files, so they move down; what is left gets a few small general primitives. After it the baseline has no `layer` and no `private` lines.
- [x] Core code out of styled files: `lazy` and `image` into the core; a menu's open state and the native context menu into the core (`menu_open`, `native_menu` answering a `NativeMenu`); `Menu::tagged` public
- [x] The behaviours into `ui/behavior/` (headless): split, pick, slider, shortcut, menu item, dialog, search, pop-up, toggle, the list's keys and presses (`list_behavior` over `ListRows` and a `Selection` that may be `multiple`, `list_rows` over its `ListBehavior`), the scroll bars (`ScrollBehavior::bar` / `thumb` / `track` by `Axis`); `field_text` with FieldStyle and `text_input`
- [x] Theme out of the core: a value store kept across frames (`environment` / `set_environment`, one mechanism with `slot`); `theme()`, `set_theme`, `follow_system` and `controls_theme` in theme.rs, the theme the app set or the system's for the appearance; the focus ring from the theme each frame unless the app set one; `take_tooltips` in the core, the tooltips drawn by the styled layer after the view; the scroll area into headless beside its bars (menus scroll in it), its knobs an environment value (`ScrollerKnob`, the appearance's by default, not the theme's)
- [x] Small public primitives for the rest, each a general modifier: `take_help`, `disabled_scope` (sets the scope, so a part enables itself), `allows_hit_testing` (SwiftUI's, for an id without the pointer), `parent_axis`, `child_count`, `a11y_labeled_pair` (SwiftUI's `accessibilityLabeledPair`, naming a form row's control), `window_toolbar_style` (SwiftUI's, the title bar's toolbar request), `Theme::inactive`, `Hotkey::from_key_event`, `request_frame`; the headless items at one public path each, at the crate's root; the edit menu into the styled layer; `response`, `partial`, `detached`, `edge_fade` not needed
- [x] The `private` rule also catches the core's crate-private fields and types (`ui.next_id`, `Node`, `Flow`), a crate-private function called after a `use`, and names a `pub fn` elsewhere shares (methods apart from free functions); child-module paths and globs in the layer rule; the `layer` rule also catches a method of `Ui` / `UiState` only a higher layer defines (it found the headless edit menu calling the styled `context_menu_at`)
- [x] The baseline's `layer` and `private` lines gone
- A scoped `.environment(v)` modifier waits for the styles (4), which need it; ControlSize and disabled keep their scopes until then

## 4. One style per control
Decided by two design reports and my vote, 2026-11-24, on d2f0ea0. One PR per item below, each from `main`:
- [x] The environment: `trait EnvironmentValue: Clone + 'static { fn default_value(ui: &Ui) -> Self }` (SwiftUI's `EnvironmentKey.defaultValue`, which may read the appearance); `ui.environment(v)` scopes a value to the next element or container (SwiftUI's `.environment`), `ui.set_environment(Some(v))` puts it window-wide, kept across frames (`None` back to the default), `ui.environment_value::<T>() -> T` reads the innermost; the window's defaults the shell installs (the styled looks) between the window's values and `default_value`. `ControlSize` and `Enabled` are values: `control_size` and `disabled` set them, `disabled_scope` and the `take_*` reads go; `Theme`, `ColorScheme` and `ScrollerKnob` declare their defaults. Steady frames allocate nothing (per-type stacks kept across frames). `Enabled(true)` re-enables a part (the ⓘ, a modal's card); a widget's pending values reach its root and what is built in it, or all it builds in a `ui.group` (SwiftUI's `Group`: menu, picker, modal, dialog, disclosure, fields, list rows, toolbar items, labeled pairs). The shell's window defaults came with the button styles
- [ ] Labels and the control root: `Icon` into the core, `Content` into headless; `ui.focusable(bool)` and `ui.pointer_style(Cursor)` (SwiftUI's) on the next element, and headless `ui.control(&Behavior)` (id, focus, the hand) over them in place of `Behavior::style`
- [x] `ButtonStyle`: `trait ButtonStyle: 'static { fn make_body(&self, ui: &mut Ui, config: ButtonConfiguration) }`, a `#[non_exhaustive]` configuration with getters (`id`, `is_pressed`, `is_hovered`, `is_focused`, `is_enabled`, `role`, `is_selected`, `is_icon_only`, `label(ui, TextStyle)`); stored as `&'static dyn ButtonStyle`, an `EnvironmentValue`, chosen with `ui.button_style(&BorderedProminentButtonStyle)` on a button or a container. `Button` (`new(impl Into<Content>)`, `icon`, `role`, `selected`, `show`) and `ui.button` in headless with `PlainButtonStyle`, the default without the shell; `BorderedButtonStyle` (the window's default, which the shell puts: `UiState::set_environment_default`), `BorderedProminentButtonStyle`, `BorderlessButtonStyle` in styled, the dialog's buttons a private style. `Button::style`, `look`, `ButtonLook`, `Theme::button`, `button_for`, `selected`, `dialog_button` and the `ButtonStyle` enum go; `Theme::button_padding(ControlSize)` lines things up with a button; a fixed width is the label's frame
- [x] `ToggleStyle`: `trait ToggleStyle: 'static { fn make_body(&self, ui: &mut Ui, config: ToggleConfiguration) }`, a `#[non_exhaustive]` configuration with getters (`id`, `is_on`, `is_pressed`, `is_hovered`, `is_focused`, `is_enabled`, `is_icon_only`, `label(ui, TextStyle)`); `ui.toggle(&mut bool, impl Into<Content>)` in headless over `toggle_behavior` with `PlainToggleStyle`, the default without the shell, chosen with `ui.toggle_style(&CheckboxToggleStyle)` on a toggle or a container; `SwitchToggleStyle` (the window's default, which the shell puts; a switch to assistive technology), `CheckboxToggleStyle`, `ButtonToggleStyle` (the bordered button tinted with the accent while on) in styled. `ui.checkbox`, `Button::selected` and `ButtonConfiguration::is_selected` go; the theme's button looks draw a `Face` (a button's state or a toggle's) with a label closure
- [x] `SliderStyle`: `trait SliderStyle: 'static { fn make_body(&self, ui: &mut Ui, config: SliderConfiguration) }`, a `#[non_exhaustive]` configuration with getters (`id`, `value`, `range`, `step`, `fraction`, `steps` (each step's value and place, 0 to 1), `tick_label(v)`, `is_held`, `is_hovered`, `is_focused`, `is_enabled`) and `root(ui)`, which makes the next element the control's root: the style calls it, first or inside a container around it (the tick labels' room over and under the track keeps the ring and the hits on the track); `ui.slider_style(&PlainSliderStyle)` on a slider or a container. `Slider` (`new`, `step`, `tick_label`, `show`) and `ui.slider` in headless with `PlainSliderStyle` (a line and a knob in the colour scheme's ink), the default without the shell; `LinearSliderStyle` (today's look) in styled, the window's default. `slider_behavior` loses its `inset`: the track is the root's box inside its horizontal padding in the last frame, the frame the pointer is mapped on already
- [ ] `TextFieldStyle`: `RoundedBorderTextFieldStyle`
- [ ] `PickerStyle`: `MenuPickerStyle` (the default), `SegmentedPickerStyle`; the style runs its behaviour (pop-up or pick); `ui.segmented` goes
- [ ] `ListStyle` and `HelpStyle`: `InsetListStyle`, `InsetGroupedListStyle`, `TooltipHelpStyle`; the tooltip's timing into headless
